1. 范围与结论

1.1 本期核心数据

  1. 用户身份（微信登录）。
  2. 参赛报名（姓名、电话、工作单位）。
  3. 微信运动步数同步。
  4. 步数兑换兑换券。
  5. 兑换券余额。
  6. 步数挑战展示（配置、规则）。
  7. 用户头像与昵称。

1.2 本期占位

  • 商城类：我的订单、积分、优惠券、卡券、收货地址、领券中心、分类、分销中心、我的收藏、我的足迹。
  • 社交类：排行榜、邀请/助力规则及加成。
  • 提醒类：每日兑换提醒开关及后台推送（仅占位）。
  • 定位图标。
  • “我”页 11 个菜单项的目标页：只梳理数据走向，不实现功能。

1.3 数据流总原则

  • 用户输入：由用户产生，前端收集并校验，后台存储。
  • 微信能力：由微信产生，前端获取，后台解密或存储。
  • 业务数据：由后台产生，前端只负责展示。
  • 后台推送：由后台产生并发送，经微信服务通知触达用户。
  • 前端不自行造业务数据；占位数据统一展示默认值（0、0%、0.00）。

  • 若用户未授权微信运动、未开启微信运动或系统限制运动数据，步数可能为 0。

报名数据规则

  • 一个用户（openid）在同一活动内只能有一条有效报名记录。
  • 一个手机号在同一活动内同一时间只能有一条有效报名记录。
  • 允许修改报名信息，修改时重新校验手机号唯一性。
  • 允许取消报名；取消后保留原记录并将状态置为“已取消”，不做物理删除。
  • 取消后允许再次报名；再次报名时复用原记录并恢复为“已报名”，同一时间同一用户/手机号只能有一条有效报名记录。
  • 不发送短信验证码，电话仅做格式校验和唯一性校验。
  • 报名成功后按钮变为“保存修改”，并展示“已报名”状态；取消报名需二次确认。

步数同步与兑换规则

  • 数据来源：微信运动 wx.getWeRunData，后台解密后按用户、日期落库。
  • 今日可兑步数建议公式：min(max(今日步数 − 今日已兑换步数, 0), 12000)。
  • 每日兑换上限：12000（用户确认；默认按步数计）。
  • 步数 → 兑换券的兑换比例由后台配置，具体比例待确认。
  • 未兑换步数每日 00:00（Asia/Shanghai）清零，兑换券余额不清零。
  • 兑换接口需要幂等控制（建议使用 requestId），避免重复点击造成重复发放。
  • 同步按钮需处理：授权拒绝、未开启微信运动、微信运动无数据、网络失败、重复同步。
  • 进入页面时先读取后台已同步数据；用户点击“同步最新步数”再触发微信运动授权与同步。

挑战数据规则

  • 挑战的开始日期、目标步数、保证金、参与人数、详细规则均由后台下发。
  • 详细规则在“更多”页面展示，建议使用后台富文本或结构化规则列表。
  • 本期挑战卡只展示后台配置（开始日期、目标步数、保证金、参与人数、详细规则）。
  • 挑战参赛流程、扣/退保证金、完成/失败判定、未参赛按钮与报名入口均占位，本期不实现；按钮“已参赛，邀请好友”按静态占位展示。

4. 核心数据实体与字段建议

以下为建议模型，用于说明数据产生、存储和展示关系；具体表结构由后台设计确定。

4.1 用户 User

字段类型必填来源说明
idbigint/string是后台用户主键
openidstring是微信 wx.login小程序用户唯一标识，唯一
unionidstring否微信绑定开放平台时使用
avatarUrlstring否chooseAvatar用户头像地址
nicknamestring否nickname 输入用户昵称
phonestring否getPhoneNumber绑定手机号，本期占位
createdAtdatetime是后台创建时间
updatedAtdatetime是后台更新时间

4.2 报名 Registration

字段类型必填来源说明
idbigint/string是后台报名记录主键
activityIdstring是后台活动 ID
userIdstring是后台关联用户
realNamestring(20)是用户输入姓名
phonestring(11)是用户输入手机号
companystring(50)是用户输入工作单位
statusenum是后台registered / cancelled
createdAtdatetime是后台报名时间
updatedAtdatetime是后台最后修改时间
cancelledAtdatetime否后台取消时间

唯一约束建议：

  • (activityId, userId) 唯一：一个用户在同一活动只能有一条报名记录。
  • (activityId, phone) 唯一：一个手机号在同一活动只能报名一次。

4.3 活动配置 ActivityConfig

字段类型必填来源说明
activityIdstring是后台活动 ID
noticeTextstring否后台首页公告文案，如“延期：10月27日-12月27日”
rulesjson/text是后台首页活动规则，建议有序数组
imageUrlstring否后台/管理端上传首页活动主图地址；由后台裁剪压缩后返回
startDatedate否后台活动开始日期
endDatedate否后台活动结束日期
statusenum是后台未开始/进行中/已结束

4.4 每日步数 DailyStep

字段类型必填来源说明
idbigint/string是后台主键
userIdstring是后台用户 ID
statDatedate是微信运动数据统计日期

7. 校验、异常与隐私

7.1 报名校验

字段规则提示
姓名必填；去除首尾空格；建议 2–20 个字符请输入姓名
电话必填；中国大陆手机号 11 位，建议正则 ^1[3-9]\d{9}$请输入正确的手机号
工作单位必填；去除首尾空格；建议 2–50 个字符请输入工作单位
  • 同一用户、同一手机号重复报名：拦截并提示“您已报名”。
  • 修改报名信息时，手机号若与其他报名记录冲突：拦截并提示。
  • 取消报名：二次确认，确认后状态置为“已取消”。

7.2 步数与兑换异常

  • 未授权微信运动：提示授权；用户拒绝后保留 0 步。
  • 未开启微信运动：提示“请先开启微信运动”。
  • 微信运动无当日数据：提示“暂无步数数据”。
  • 同步失败：保留上次数据，提示重试。
  • 可兑步数为 0：兑换按钮不可用或提示“暂无可兑换步数”。
  • 超过每日上限 12000：按上限计算，提示当日上限。
  • 兑换请求重复：后台按 requestId 幂等处理。

7.3 隐私与合规建议

  • 收集姓名、电话、工作单位、微信运动步数前，应提供隐私政策并获得用户同意。
  • 手机号属于个人信息，后台应加密存储、限制访问权限。
  • 微信运动步数仅用于本次活动，不向无关第三方提供。
  • 头像、昵称通过微信授权获取，用户可拒绝；拒绝时展示默认头像/昵称。
  • 报名页面建议增加隐私协议勾选；具体交互待确认。
  • 数据保留期限、注销/删除机制待运营确认。
