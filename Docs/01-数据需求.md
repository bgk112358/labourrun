## 1. 范围与结论

### 1.1 本期核心数据

1. 用户身份（微信登录）。
2. 参赛报名（姓名、电话、工作单位）。
3. 微信运动步数同步。
4. 步数兑换兑换券。
5. 兑换券余额。
6. 步数挑战展示（配置、规则）。
7. 用户头像与昵称。

### 1.2 本期占位

- 商城类：我的订单、积分、优惠券、卡券、收货地址、领券中心、分类、分销中心、我的收藏、我的足迹。
- 社交类：排行榜、邀请/助力规则及加成。
- 提醒类：每日兑换提醒开关及后台推送（仅占位）。
- 定位图标。
- “我”页 11 个菜单项的目标页：只梳理数据走向，不实现功能。

### 1.3 数据流总原则

- **用户输入**：由用户产生，前端收集并校验，后台存储。
- **微信能力**：由微信产生，前端获取，后台解密或存储。
- **业务数据**：由后台产生，前端只负责展示。
- **后台推送**：由后台产生并发送，经微信服务通知触达用户。
- 前端不自行造业务数据；占位数据统一展示默认值（0、0%、0.00）。

## 2. 数据来源分类

### 2.1 用户手动输入

| 数据项 | 页面 | 输入方式 | 去向 | 本期状态 |
|---|---|---|---|---|
| 姓名 | 首页 | 文本输入，必填 | 报名接口 → 后台 | 核心 |
| 电话 | 首页 | 文本/数字输入，必填，11 位 | 报名接口 → 后台 | 核心 |
| 工作单位 | 首页 | 文本输入，必填 | 报名接口 → 后台 | 核心 |

说明：本期报名电话为手动输入，**不需要短信验证码**。

### 2.2 微信/手机能力获取

| 能力 | 接口/方式 | 产生数据 | 用途 | 前置条件 | 本期状态 |
|---|---|---|---|---|---|
| 登录身份 | `wx.login` → code → 后台 `code2Session` | openid、session_key | 用户身份、所有用户数据的前提 | 无 | 核心 |
| 微信运动步数 | `wx.getWeRunData` → encryptedData/iv → 后台解密 | 当日及历史步数 | 步数同步、兑换券兑换 | 用户授权“微信运动”，且已开启微信运动 | 核心 |
| 头像 | `button open-type="chooseAvatar"` | 临时头像文件 | 用户头像 | 用户点击选择 | 核心 |
| 昵称 | `input type="nickname"` | 昵称文本 | 用户昵称 | 用户填写 | 核心 |
| 手机号 | `button open-type="getPhoneNumber"` | 手机号 code/加密数据 | 绑定手机号 | 企业认证；用户点击授权 | 占位 |
| 收货地址 | `wx.chooseAddress` | 收货人、电话、地址 | 收货地址 | `scope.address` 授权 | 占位 |
| 定位 | `wx.getLocation` / `wx.chooseLocation` | 经纬度/城市 | 定位图标 | 隐私声明、用户授权 | 占位 |
| 订阅消息 | `wx.requestSubscribeMessage` | 订阅授权结果 | 每日兑换提醒 | 用户点击；模板待配置 | 占位 |
| 分享邀请 | `onShareAppMessage` + 邀请参数 | 分享路径、邀请关系 | 邀请好友 | 用户点击分享 | 占位 |
| 客服 | `button open-type="contact"` | 客服会话 | 联系客服 | 小程序后台配置客服 | 占位 |
| 系统信息 | `wx.getWindowInfo` / `wx.getSystemInfoSync` | 状态栏、安全区尺寸 | 页面布局 | 无 | 核心（仅 UI） |

注意：

- `wx.getWeRunData` 返回的是加密数据，必须由后台使用 `session_key` 解密，前端不能直接解析。
- 头像、昵称不能静默获取，必须由用户通过 `chooseAvatar` 和 `nickname` 输入产生。
- 若用户未授权微信运动、未开启微信运动或系统限制运动数据，步数可能为 0。

#### 报名数据规则

- 一个用户（openid）在同一活动内只能有一条有效报名记录。
- 一个手机号在同一活动内同一时间只能有一条有效报名记录。
- 允许修改报名信息，修改时重新校验手机号唯一性。
- 允许取消报名；取消后保留原记录并将状态置为“已取消”，不做物理删除。
- 取消后允许再次报名；再次报名时复用原记录并恢复为“已报名”，同一时间同一用户/手机号只能有一条有效报名记录。
- 不发送短信验证码，电话仅做格式校验和唯一性校验。
- 报名成功后按钮变为“保存修改”，并展示“已报名”状态；取消报名需二次确认。

#### 步数同步与兑换规则

- 数据来源：微信运动 `wx.getWeRunData`，后台解密后按用户、日期落库。
- 今日可兑步数建议公式：`min(max(今日步数 − 今日已兑换步数, 0), 12000)`。
- 每日兑换上限：12000（用户确认；默认按步数计）。
- 步数 → 兑换券的兑换比例由后台配置，具体比例**待确认**。
- 未兑换步数每日 00:00（Asia/Shanghai）清零，兑换券余额不清零。
- 兑换接口需要幂等控制（建议使用 requestId），避免重复点击造成重复发放。
- 同步按钮需处理：授权拒绝、未开启微信运动、微信运动无数据、网络失败、重复同步。
- 进入页面时先读取后台已同步数据；用户点击“同步最新步数”再触发微信运动授权与同步。

#### 挑战数据规则

- 挑战的开始日期、目标步数、保证金、参与人数、详细规则均由后台下发。
- 详细规则在“更多”页面展示，建议使用后台富文本或结构化规则列表。
- 本期挑战卡只展示后台配置（开始日期、目标步数、保证金、参与人数、详细规则）。
- 挑战参赛流程、扣/退保证金、完成/失败判定、未参赛按钮与报名入口均**占位**，本期不实现；按钮“已参赛，邀请好友”按静态占位展示。

## 4. 核心数据实体与字段建议

> 以下为建议模型，用于说明数据产生、存储和展示关系；具体表结构由后台设计确定。

### 4.1 用户 User

| 字段 | 类型 | 必填 | 来源 | 说明 |
|---|---|---|---|---|
| `id` | bigint/string | 是 | 后台 | 用户主键 |
| `openid` | string | 是 | 微信 `wx.login` | 小程序用户唯一标识，唯一 |
| `unionid` | string | 否 | 微信 | 绑定开放平台时使用 |
| `avatarUrl` | string | 否 | `chooseAvatar` | 用户头像地址 |
| `nickname` | string | 否 | `nickname` 输入 | 用户昵称 |
| `phone` | string | 否 | `getPhoneNumber` | 绑定手机号，本期占位 |
| `createdAt` | datetime | 是 | 后台 | 创建时间 |
| `updatedAt` | datetime | 是 | 后台 | 更新时间 |

### 4.2 报名 Registration

| 字段 | 类型 | 必填 | 来源 | 说明 |
|---|---|---|---|---|
| `id` | bigint/string | 是 | 后台 | 报名记录主键 |
| `activityId` | string | 是 | 后台 | 活动 ID |
| `userId` | string | 是 | 后台 | 关联用户 |
| `realName` | string(20) | 是 | 用户输入 | 姓名 |
| `phone` | string(11) | 是 | 用户输入 | 手机号 |
| `company` | string(50) | 是 | 用户输入 | 工作单位 |
| `status` | enum | 是 | 后台 | `registered` / `cancelled` |
| `createdAt` | datetime | 是 | 后台 | 报名时间 |
| `updatedAt` | datetime | 是 | 后台 | 最后修改时间 |
| `cancelledAt` | datetime | 否 | 后台 | 取消时间 |

唯一约束建议：

- `(activityId, userId)` 唯一：一个用户在同一活动只能有一条报名记录。
- `(activityId, phone)` 唯一：一个手机号在同一活动只能报名一次。

### 4.3 活动配置 ActivityConfig

| 字段 | 类型 | 必填 | 来源 | 说明 |
|---|---|---|---|---|
| `activityId` | string | 是 | 后台 | 活动 ID |

## 6. 呈现与格式约定

### 6.1 数值与文本格式

| 数据类型 | 格式 | 示例 | 说明 |
|---|---|---|---|
| 兑换券余额 | 保留 2 位小数 | `19.00` | 顶部使用金币/¥ 图标；是否等价人民币待确认 |

| 百分比 | 整数 + `%` | `0%` | 占位状态显示 0% |
| 人数/数量 | 整数 + 单位 | `309人`、`0张` | 占位状态显示 0 |
| 挑战日期 | `YYYY-MM-DD开始` | `2026-11-18开始` | 由后台下发 |
| 公告日期 | 后台文案原样展示 | `延期：10月27日-12月27日` | 前端不解析年份 |

### 6.2 表单与按钮状态

- 报名表单字段均必填，label 后保留红色 `*`。
- 电话输入框右侧保留“11位”提示；不使用短信验证码。
- 底部固定主按钮：
  - 未报名：`提交报名`
  - 已报名：`保存修改`
  - 取消报名：独立文字按钮或次级按钮，需二次确认。
- 已报名状态：表单回填，展示“已报名”标识。
- 已取消状态：展示“已取消”，并允许再次报名；再次报名复用原记录并恢复为“已报名”。
- 提交成功/失败使用 Toast 或页面内提示；具体样式待设计。

### 6.3 空状态与异常状态

- 数字类占位统一显示 `0`；兑换券显示 `0.00`。
- 好友助力“+”位保留 4 个空位。
- 微信运动未授权/无数据：步数显示 `0`，同步时提示用户开启微信运动或前往设置授权。
- 网络异常：保留上次数据，提示“加载失败，请重试”。
- 兑换失败：提示失败原因，不扣减步数、不增加兑换券。

### 6.4 刷新时机

- 首页：进入页面时刷新公告、规则、报名状态。
- 步数宝：进入页面时刷新兑换券余额、可兑步数、挑战数据；点击“同步最新步数”时同步微信运动；兑换成功后刷新余额和可兑步数。
- 我：进入页面时刷新头像、昵称、占位统计数字。
- 当前未配置下拉刷新；是否需要待确认。

## 7. 校验、异常与隐私

### 7.1 报名校验

| 字段 | 规则 | 提示 |
|---|---|---|
| 姓名 | 必填；去除首尾空格；建议 2–20 个字符 | 请输入姓名 |
| 电话 | 必填；中国大陆手机号 11 位，建议正则 `^1[3-9]\d{9}$` | 请输入正确的手机号 |
| 工作单位 | 必填；去除首尾空格；建议 2–50 个字符 | 请输入工作单位 |

- 同一用户、同一手机号重复报名：拦截并提示“您已报名”。
- 修改报名信息时，手机号若与其他报名记录冲突：拦截并提示。
- 取消报名：二次确认，确认后状态置为“已取消”。

### 7.2 步数与兑换异常

- 未授权微信运动：提示授权；用户拒绝后保留 0 步。
- 未开启微信运动：提示“请先开启微信运动”。
- 微信运动无当日数据：提示“暂无步数数据”。
- 同步失败：保留上次数据，提示重试。
- 可兑步数为 0：兑换按钮不可用或提示“暂无可兑换步数”。
- 超过每日上限 12000：按上限计算，提示当日上限。
- 兑换请求重复：后台按 `requestId` 幂等处理。

### 7.3 隐私与合规建议

- 收集姓名、电话、工作单位、微信运动步数前，应提供隐私政策并获得用户同意。
- 手机号属于个人信息，后台应加密存储、限制访问权限。
- 微信运动步数仅用于本次活动，不向无关第三方提供。
- 头像、昵称通过微信授权获取，用户可拒绝；拒绝时展示默认头像/昵称。
- 报名页面建议增加隐私协议勾选；具体交互待确认。
- 数据保留期限、注销/删除机制待运营确认。
