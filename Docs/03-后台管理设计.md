## 1. 目标与范围

### 1.1 目标

提供一个浏览器访问的后台管理界面，让运营人员可以：

1. 编辑并发布首页活动须知、活动规则、活动时间、活动状态。
2. 编辑并发布步数挑战的标题、时间、目标步数、保证金、参与人数、详细规则。
3. 查看报名列表、搜索、查看详情、导出 CSV。
4. 查看管理员操作审计日志。
5. 管理管理员账号（可选，super_admin 专属）。

### 1.2 不在本期范围

- 不修改微信小程序前端。
- 不做商城、订单、优惠券、卡券、积分、排行榜、邀请/助力、每日提醒。
- 不做用户数据编辑/删除；报名数据只读。
- 不做多租户、工作流引擎、富文本图片上传。
- 不做小程序用户的头像/手机号管理。

### 1.3 设计原则

- **前后端分离但不拆后端**：管理界面是新目录；管理 API 留在现有 FastAPI。
- **管理端鉴权独立**：管理员账号密码 + 独立 JWT；不接受小程序用户 token。
- **所有写操作有审计**：记录操作人、时间、IP、修改前后内容。
- **配置即发布**：保存后立即生效；是否增加草稿/发布流程待确认。
- **最小权限**：超级管理员与运营管理员分权。

## 2. 总体架构

### 2.1 链路

```
浏览器（LabourRunAdmin）
   │  HTTPS / Bearer admin JWT
   ▼
LabourRunBack /api/v1/admin
   │  管理员鉴权、权限校验、审计
   ├── SQLite（admin_users / admin_audit_logs / activities / challenges / registrations）
   └── 现有 service / 数据模型
```

### 2.2 目录结构

```
LabourRun/

  LabourRunBack/           # FastAPI 后端
    app/

        auth.py            # 管理员登录/当前管理员依赖

        content.py         # 活动/挑战配置管理
        registrations.py   # 报名列表/导出
        audit.py           # 审计日志
        models.py          # 管理端请求/响应模型
        service.py         # 管理端业务逻辑
        security.py        # scrypt、admin JWT、登录限流
        bootstrap.py       # 初始化管理员 CLI
      ...                  # 现有小程序 API
  LabourRunAdmin/          # 新增：管理端 Web 前端
    package.json
```

### 2.3 技术栈建议

| 层 | 选型 | 说明 |
|---|---|---|
| 管理端前端 | Vue 3 + Vite + TypeScript | 桌面端后台，开发快 |
| UI 组件 | Element Plus | 表格、表单、日期选择、弹窗齐全 |
| 状态/路由 | Pinia + Vue Router | 登录态、路由守卫 |
| HTTP | Axios | 拦截器统一带 token、处理 401 |
| 后端 | 现有 FastAPI | 新增 admin 模块，不另起服务 |
| 管理员密码 | scrypt（标准库） | N=16384, r=8, p=1；避免新增依赖 |
| 管理员 token | JWT（独立 secret/audience） | 8 小时有效 |
| 数据库 | 现有 SQLite | 新增管理员/审计表 |

如果团队更熟悉 React + Ant Design，可替换前端栈；管理 API 不变。

### 2.4 部署方式

- 开发：
  - 后端：先激活 Conda 环境（环境变量见 `Docs/04-部署与使用.md` 3.2），再 `uvicorn app.server:app --reload --port 3000`
  - 管理端 `npm run dev`，Vite 代理 `/api` 到 `http://127.0.0.1:3000`
- 生产（推荐二选一）：
  1. `npm run build` 后，由 FastAPI 挂载 `LabourRunAdmin/dist` 到 `/admin`，SPA 路由回退到 `index.html`；单服务部署。
  2. 由 Nginx 托管静态文件，`/api` 反向代理到 FastAPI；适合已有网关的环境。
- 管理端建议使用独立域名或 `/admin` 路径，不对外暴露到小程序请求域名。

## 3. 功能设计

### 3.1 页面清单

| 页面 | 路由 | 功能 | 权限 |
|---|---|---|---|
| 登录 | `/login` | 管理员账号密码登录 | 公开 |
| 概览 | `/` | 当前活动/挑战状态、报名数、最近审计 | 所有管理员 |
| 活动管理 | `/activity` | 公告、规则、时间、状态 | super_admin / operator |
| 挑战管理 | `/challenge` | 标题、时间、目标、保证金、人数、规则 | super_admin / operator |
| 报名管理 | `/registrations` | 列表、搜索、详情、导出 CSV | super_admin / operator |
| 审计日志 | `/audit-logs` | 操作记录查询 | super_admin / operator（只读） |
| 管理员账号 | `/admins` | 新增、禁用、重置密码、角色 | super_admin |

### 3.2 登录页

- 字段：用户名、密码。
- 登录成功：保存 admin token 到 `sessionStorage`，跳转概览。
- 登录失败：提示“用户名或密码错误”，不区分账号不存在/密码错误。
- 连续失败限流：同一用户名 + IP，15 分钟内最多 5 次失败。
- 账号禁用：返回“账号已禁用”。

### 3.3 概览页

展示：

- 当前活动：名称、状态、公告摘要、更新时间。
- 当前挑战：标题、状态、目标步数、参与人数、更新时间。
- 报名总数、今日新增报名数。
- 最近 5 条审计日志。

### 3.4 活动管理页

表单字段：

| 字段 | 控件 | 校验 |
|---|---|---|
| 活动名称 `name` | 输入框 | 必填，2–50 字 |
| 公告文案 `noticeText` | 多行文本 | 必填，≤200 字 |
| 活动规则 `rules` | 动态列表 | 1–20 条；每条 `no` + `text` |
| 开始日期 `startDate` | 日期选择 | 可空；不晚于结束日期 |
| 结束日期 `endDate` | 日期选择 | 可空；不早于开始日期 |
| 状态 `status` | 下拉 | `upcoming` / `ongoing` / `ended` |

规则编辑：

- 默认展示现有 4 条规则，支持新增、删除、上移、下移。
- `no` 自动生成 `01`、`02`…，也允许手动修改；同一活动内不重复。
- `text` 多行文本，每条 ≤500 字。
- 提供“恢复为当前线上内容”按钮（未保存前）。
- 右侧或弹窗提供小程序端效果预览（公告条 + 规则卡）。

保存：

- 点击“保存并发布”，调用 `PUT /api/v1/admin/activity`。
- 成功后刷新表单和概览，提示“已发布”。
- 保存前若有未保存修改，离开页面需二次确认。

### 3.5 挑战管理页

表单字段：

| 字段 | 控件 | 校验 |
|---|---|---|
| 挑战名称 `title` | 输入框 | 必填，2–50 字 |
| 开始日期 `startDate` | 日期选择 | 必填 |
| 结束日期 `endDate` | 日期选择 | 可空；不早于开始日期 |
| 目标步数 `targetSteps` | 数字输入 | 正整数，建议 1–100000 |
| 保证金 `depositCoupons` | 金额输入（元） | ≥0，最多 2 位小数；提交转整数分 |
| 参与人数 `participantCount` | 数字输入 | ≥0 整数，可人工修正 |
| 详细规则 `rules` | 动态列表 | 1–20 条；每条 `title` + `content` |
| 状态 `status` | 下拉 | `upcoming` / `ongoing` / `ended` |

规则编辑：

- 每条包含标题和内容，支持新增、删除、排序。
- 内容支持多行文本，≤1000 字。
- 提供小程序“更多”页预览。

保存：同活动管理，调用 `PUT /api/v1/admin/challenge`。

### 3.6 报名管理页

列表列：

| 列 | 说明 |
|---|---|
| 姓名 | `realName` |
| 手机号 | 默认脱敏，如 `138****8000` |
| 工作单位 | `company` |
| 状态 | 已报名 / 已取消 |
| 报名时间 | `createdAt` |
| 更新时间 | `updatedAt` |
| 操作 | 查看详情 |

筛选：

- 关键词：姓名/手机号/工作单位模糊匹配。
- 状态：全部 / 已报名 / 已取消。
- 时间范围：报名时间。

详情抽屉：

- 完整姓名、手机号、单位、状态、报名/更新时间、取消时间。
- 只读，不提供编辑/删除。

导出：

- `GET /api/v1/admin/registrations/export`，CSV，UTF-8 BOM，字段同列表。
- 是否允许 operator 导出完整手机号待确认。

### 3.7 审计日志页

列表字段：

- 时间、管理员、操作类型、资源类型、资源 ID、IP。
- 操作类型：`login`、`logout`、`update_activity`、`update_challenge`、`create_admin`、`update_admin`、`reset_password`。
- 支持按管理员、资源类型、时间范围筛选。
- 详情查看 `before` / `after` JSON。

### 3.8 管理员账号页（本期未实现）

- 列表：用户名、显示名、角色、状态、最后登录时间。
- 新增管理员：用户名、显示名、初始密码、角色。
- 禁用/启用账号。
- 重置密码。
- 不能禁用自己；不能把最后一个 super_admin 降级/禁用。

## 4. 管理员认证与权限

### 4.1 账号与密码

- 管理员账号独立于微信用户，存 `admin_users`。
- 用户名唯一，3–32 位字母/数字/下划线。
- 密码使用 Python 标准库 `hashlib.scrypt` 哈希（N=16384, r=8, p=1），不存明文。
- 密码策略：至少 10 位，包含字母和数字；具体规则待确认。
- 首次初始化通过 CLI 创建 super_admin，不使用默认弱密码。

### 4.2 管理员 JWT

- 独立 `ADMIN_JWT_SECRET`，不与小程序 `JWT_SECRET` 共用。
- Claims：
  - `sub`：admin id
  - `aud`：`labourrun-admin`
  - `role`：`super_admin` / `operator`
  - `typ`：`admin`
  - `iat` / `exp`
- 有效期：8 小时（可配置 `ADMIN_JWT_TTL_SECONDS`）。
- 管理端请求头：`Authorization: Bearer <adminToken>`。
- 小程序用户 token 不能访问 `/api/v1/admin/*`；管理员 token 也不能访问小程序用户接口。

### 4.3 角色与权限

| 操作 | super_admin | operator |
|---|---|---|
| 查看概览 | ✅ | ✅ |
| 编辑活动/挑战 | ✅ | ✅ |
| 查看报名列表/详情 | ✅ | ✅ |
| 导出报名 CSV | ✅ | 待确认 |
| 查看审计日志 | ✅ | ✅ |
| 管理管理员账号 | ✅ | ❌ |

- 如果只需要一个角色，可先只保留 `super_admin`；表结构仍保留 `role` 字段。
- 权限校验在管理 API 层实现，不依赖前端隐藏按钮。

### 4.4 初始化管理员

推荐 CLI：

```bash
cd LabourRunBack
python -m app.admin.bootstrap \
  --username admin \
  --password '请替换为强密码' \
  --display-name '超级管理员'
```

行为：

- 若 `admin_users` 为空，创建 `super_admin`。
- 若用户名已存在，提示并退出。
- 不把密码写入代码或日志。

备选：环境变量 `ADMIN_BOOTSTRAP_USERNAME` / `ADMIN_BOOTSTRAP_PASSWORD` 首次启动时创建；安全性略低，待确认。

### 4.5 登录安全

- 登录失败统一提示“用户名或密码错误”。
- 同一用户名 + IP 15 分钟内 5 次失败后临时锁定。
- 记录登录成功/失败审计（失败可不记密码）。
- 管理端 token 存 `sessionStorage`，关闭标签页后失效；不使用 localStorage 长期保存。
- 退出登录：前端清除 token；后端记录审计。

## 5. 数据模型

### 5.1 新增表

**admin_users**

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | TEXT PK | `adm_...` |
| `username` | TEXT UNIQUE | 登录名 |
| `password_hash` | TEXT | scrypt（标准库） |
| `display_name` | TEXT | 显示名 |
| `role` | TEXT | `super_admin` / `operator` |
| `status` | TEXT | `active` / `disabled` |
| `last_login_at` | TEXT | 最后登录时间 |
| `created_at` | TEXT | 创建时间 |
| `updated_at` | TEXT | 更新时间 |

**admin_audit_logs**

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | TEXT PK | `aud_...` |
| `admin_id` | TEXT | 操作人 ID |
| `admin_username` | TEXT | 操作人用户名快照 |
| `action` | TEXT | 操作类型 |
| `resource_type` | TEXT | `activity` / `challenge` / `admin` / `auth` |
| `resource_id` | TEXT | 资源 ID |
| `before_json` | TEXT | 修改前快照 |
| `after_json` | TEXT | 修改后快照 |
| `ip` | TEXT | 客户端 IP |
| `user_agent` | TEXT | 浏览器 UA |
| `created_at` | TEXT | 时间 |

索引：

- `admin_users.username` 唯一。
- `admin_audit_logs.created_at DESC`。
- `admin_audit_logs.admin_id`、`resource_type`。

### 5.2 现有表调整

- `activities` / `challenges` 增加 `updated_by_admin_id`（可空），用于页面显示最后修改人；详细变更看审计日志。
- 迁移方式：启动时检查列是否存在，不存在则 `ALTER TABLE ADD COLUMN`；SQLite 不支持复杂迁移，需保持简单。
- 不新增草稿表；如需要草稿/发布流程，再增加 `draft_json` 或 `status=draft`。

### 5.3 管理端不建的表

- 不建商城、订单、积分、优惠券、卡券、排行榜、邀请、提醒相关表。
- 不复制小程序用户表；管理端直接读现有 `registrations`、`users`。

## 6. API 设计

### 6.1 通用约定

| 项目 | 约定 |
|---|---|
| Base URL | `/api/v1/admin` |
| 鉴权 | `Authorization: Bearer <adminToken>` |
| 响应包 | 与小程序 API 一致：`{ code, message, data, requestId }` |
| 分页 | `page`、`pageSize`，返回 `{ list, total, page, pageSize }` |
| 时间 | ISO 8601 |
| 金额 | 字符串，2 位小数；数据库存整数分 |
| 请求 ID | 响应头 `X-Request-Id` |

管理端错误码：

| code | HTTP | 含义 |
|---|---|---|
| 1101 | 401 | 管理员未登录 |
| 1102 | 401 | 管理员 token 过期 |
| 1103 | 403 | 无权限 |
| 1104 | 401 | 用户名或密码错误 |
| 1105 | 403 | 管理员账号已禁用 |
| 1106 | 404 | 管理员不存在 |
| 1107 | 409 | 用户名已存在 |
| 1108 | 409 | 不能禁用自己/最后一个超级管理员 |
| 1109 | 400 | 密码不符合策略 |
| 1110 | 429 | 登录失败次数过多 |
| 1201 | 404 | 活动不存在 |
| 1202 | 404 | 挑战不存在 |
| 1203 | 422 | 配置内容不合法 |
| 1204 | 404 | 报名记录不存在 |
| 4000 | 400 | 参数校验失败 |
| 9001 | 500 | 服务器内部错误 |

### 6.2 管理员登录

```
POST /api/v1/admin/auth/login
```

请求：

```json
{
  "username": "admin",
  "password": "********"
}
```

响应：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "token": "eyJ...",
    "expiresIn": 28800,
    "admin": {
      "id": "adm_...",
      "username": "admin",
      "displayName": "超级管理员",
      "role": "super_admin"
    }
  },
  "requestId": "..."
}
```

错误：1104、1105、4000。

### 6.3 当前管理员

```
GET /api/v1/admin/auth/me
Authorization: Bearer <adminToken>
```

响应 `data`：管理员对象。

### 6.4 退出登录

```
POST /api/v1/admin/auth/logout
Authorization: Bearer <adminToken>
```

- 服务端记录审计；JWT 无状态，不主动吊销。
- 前端清除 `sessionStorage` token。
- 响应 `data: null`。

```json
  "startDate": "2026-10-27",
  "endDate": "2026-12-27",
  "status": "ongoing"
}
```

校验：

- `name` 必填，2–50 字。
- `noticeText` 必填，≤200 字。
- `rules` 1–20 条，`no` 唯一，`text` 1–500 字。
- `startDate` / `endDate` 可空；两者都有时 start ≤ end。
- `status` 枚举。

响应 `data`：更新后的活动配置。

副作用：

- 写审计日志 `update_activity`，记录 before/after。
- 更新 `updated_by_admin_id`、`updated_at`。
- 小程序下次 `GET /home` 立即看到新内容。

## 7. 前端设计

### 7.1 布局

- 左侧固定菜单：概览、活动管理、挑战管理、报名管理、审计日志、管理员账号（按权限显示）。
- 顶部：当前管理员、角色、退出登录。
- 内容区：面包屑 + 页面内容。
- 桌面优先，最小宽度 1024px；窄屏可折叠菜单。

### 7.2 登录态

- `Pinia` 存 `token`、`admin`。
- token 存 `sessionStorage`。
- Axios 请求拦截器自动加 `Authorization`。
- 响应拦截器：
  - `code=0` 返回 data。
  - 401/1101/1102 清除 token，跳登录。
  - 其他错误用 Element Plus `ElMessage` 提示。
- 路由守卫：无 token 跳 `/login`；已登录访问 `/login` 跳概览。

### 7.3 表单交互

- 活动/挑战页面加载时调 GET，填充表单。
- 保存按钮 loading；成功后提示“已发布”。
- 未保存修改离开页面时 `onBeforeRouteLeave` 二次确认。
- 规则编辑器支持新增/删除/上移/下移；空规则阻止保存。
- 日期选择器输出 `YYYY-MM-DD`。
- 金额输入以元为单位，提交时转字符串两位小数；后端转分。
- 提供“预览”抽屉，按小程序样式展示公告、规则、挑战卡/更多页内容。

### 7.4 表格与导出

- Element Plus `el-table` + `el-pagination`。
- 搜索栏：关键词、状态下拉、查询/重置。
- 报名详情用抽屉，不跳页。
- 导出按钮下载 CSV；失败提示。

### 7.5 构建与部署

- 开发：`npm run dev`，Vite 代理 `/api` 到 `http://127.0.0.1:3000`。
- 构建：`npm run build`，输出 `dist/`。
- 生产：
  - 方案 A：FastAPI 挂载 `LabourRunAdmin/dist` 到 `/admin`，SPA fallback。
  - 方案 B：Nginx 托管 `dist`，反代 `/api`。
- 管理端页面加 `noindex`，不建议被搜索引擎收录。

## 8. 发布、审计与缓存

### 8.1 发布方式

本期建议 **直接保存并发布**：

- `PUT` 成功即写入 `activities` / `challenges`。
- 小程序下次请求立即读取新配置。
- 不做草稿、定时发布、版本回滚。

如需要草稿/审核/定时发布，需要增加：

- `draft_json` 或独立版本表。
- `publish_at`、`published_by`、`version`。
- 前端“保存草稿 / 预览 / 发布”三个动作。

### 8.2 审计

所有写操作记录：

- 谁：admin_id、admin_username。
- 什么：action、resource_type、resource_id。
- 前后：before_json、after_json。
- 环境：IP、User-Agent、时间。

审计日志只读，不提供删除接口；保留期限待确认（建议 180 天）。

### 8.3 缓存

- 后端不缓存活动/挑战配置，直接读 SQLite。
- 小程序端按现有 onShow 刷新，无需管理端通知。
- 如果后续加 CDN/缓存，需要在发布后主动失效。

## 9. 安全设计

- 管理端 API 与小程序 API 使用不同 JWT secret、audience。
- 管理员密码 scrypt 哈希；不记录明文。
- 登录限流；失败提示不区分账号不存在/密码错误。
- 所有写操作审计。
- 管理端 token 存 `sessionStorage`，8 小时过期。
- 生产必须 HTTPS；建议管理端限制 IP/VPN 访问。
- 管理端 API 不暴露给小程序；不在小程序代码中引用。
- CORS：
  - 开发用 Vite 代理，避免 CORS。
  - 生产同源部署；如跨域，配置 `ADMIN_ORIGINS` 白名单。
- 管理端页面 `X-Frame-Options: DENY`、`X-Content-Type-Options: nosniff`、CSP（部署层配置）。
- 管理员账号管理仅 super_admin；不能禁用自己/最后一个 super_admin。
- 报名数据只读；导出权限待确认。
