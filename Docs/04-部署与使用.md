## 1. 部署架构

### 1.1 组成

```
微信小程序（LabourRunMiniProgram）
        │ HTTPS /api/v1/*
        ▼
Nginx（443） ──────────────► FastAPI（127.0.0.1:3000）
        │                         │
        │ /admin/                 ├── SQLite（data/labourrun.sqlite）
        ▼                         └── 微信 code2Session
管理端（LabourRunAdmin dist）
```

| 组件 | 作用 | 部署位置 |
|---|---|---|
| `LabourRunBack` | 小程序 API、管理 API、SQLite | 应用服务器 |
| `LabourRunAdmin` | 浏览器管理界面 | 构建后由 FastAPI 或 Nginx 托管 |
| `LabourRunMiniProgram` | 微信小程序界面 | 微信开发者工具上传 |
| SQLite | 业务数据、管理员、审计日志 | 应用服务器本地文件 |
| Nginx | HTTPS、反向代理、静态文件 | 应用服务器 |

### 1.2 端口

| 端口 | 用途 | 是否对外 |
|---|---|---|
| 3000 | FastAPI | 否，建议只监听 `127.0.0.1` |
| 5173 | 管理端 Vite 开发服务器 | 仅开发；默认监听 `0.0.0.0`，可局域网访问 |
| 80 | HTTP 跳转 HTTPS | 是 |
| 443 | HTTPS / API / 管理端 | 是 |

### 1.3 推荐目录

```
/opt/labourrun/
  LabourRunBack/
    app/
    tests/
    requirements.txt
    data/
      labourrun.sqlite
    uploads/
      activity/
  LabourRunAdmin/
    dist/
  backup/

Conda 环境：labourrun（实际路径由 conda info --base 决定）
```

## 2. 部署前准备

### 2.1 服务器

建议：

- Linux（Ubuntu 22.04/24.04 或同类）
- 1 核 CPU、1 GB 内存以上
- Python 3.12/3.13/3.14（通过 Conda 管理）
- Node.js 20+、npm 10+
- Conda 或 Miniconda
- Nginx
- 可选的 `sqlite3` 命令行工具
- 已备案域名和 HTTPS 证书（微信小程序要求 HTTPS）

当前验证环境：Python 3.14.6、Node 20.20.2、npm 10.8.2、Vite 5.4.21。管理端 `element-plus` 固定为 **2.9.3**，避免较新版本依赖的 `@vueuse/core@15` 要求 Node 22。

检查：

```bash
python3 --version
node -v
npm -v
nginx -v
```

### 2.2 微信小程序信息

在微信公众平台准备：

- 小程序 AppID：`wx553877a9e7439113`（当前 `project.config.json` 中的值）
- AppSecret
- 服务器域名：`https://api.example.com`
- 小程序类目、隐私保护指引
- 微信运动相关权限说明

微信公众平台配置路径：

```
开发管理 → 开发设置 → 服务器域名 → request 合法域名
```

填入：

```
https://api.example.com
```

当前功能不需要 `uploadFile` 合法域名（未实现头像上传）。

### 2.3 生成密钥

```bash
openssl rand -hex 32
```

生成两个不同的值：

- `JWT_SECRET`：小程序用户 JWT
- `ADMIN_JWT_SECRET`：管理员 JWT

要求至少 32 字节，不要复用，不要提交到代码仓库。

### 2.4 创建运行用户和目录

```bash
sudo useradd --system --create-home --shell /usr/sbin/nologin labourrun
sudo mkdir -p /opt/labourrun
sudo chown -R labourrun:labourrun /opt/labourrun
```

把 `LabourRunBack` 和 `LabourRunAdmin` 放到 `/opt/labourrun/` 下。

## 3. 后端部署

### 3.1 Conda 环境与依赖

本文按 Conda 管理 Python 环境，不使用 `venv` 和 `.env` 文件。

```bash
# 如果 conda 不在 PATH，先加载 conda
source /opt/miniconda3/etc/profile.d/conda.sh

conda create -n labourrun python=3.12 -y
conda activate labourrun
python -m pip install --upgrade pip
python -m pip install -r /opt/labourrun/LabourRunBack/requirements.txt
```

验证：

```bash
python -c "import fastapi, pydantic, jwt, cryptography, httpx; print('ok')"
```

说明：

- `/opt/miniconda3` 替换为实际 `conda info --base` 的路径。
- Python 3.12/3.13 推荐；当前环境 3.14.6 也已验证。
- 如果 Conda 由 root 安装，确保 `labourrun` 用户对 Conda 环境目录有读/执行权限。

### 3.2 配置 Conda 环境变量

不使用 `.env` 文件；使用 Conda 的 per-environment 变量。设置后需要重新激活环境才会生效。

```bash
source /opt/miniconda3/etc/profile.d/conda.sh
conda activate labourrun

# 数据目录
mkdir -p /opt/labourrun/LabourRunBack/data
chown -R labourrun:labourrun /opt/labourrun/LabourRunBack/data

conda env config vars set \
  DB_PATH=/opt/labourrun/LabourRunBack/data/labourrun.sqlite \
  JWT_SECRET='替换为32字节以上随机值' \
  JWT_TTL_SECONDS=604800 \
  WX_APPID=wx553877a9e7439113 \
  WX_SECRET='替换为小程序AppSecret' \
  WX_MOCK=0 \
  ADMIN_JWT_SECRET='替换为另一个32字节以上随机值' \
  ADMIN_JWT_TTL_SECONDS=28800 \
  UPLOAD_DIR=/opt/labourrun/LabourRunBack/uploads \
  PUBLIC_BASE_URL=https://api.example.com \
  -n labourrun

conda deactivate
conda activate labourrun
conda env config vars list -n labourrun
```

说明：

| 变量 | 生产建议 |
|---|---|
| `DB_PATH` | 使用绝对路径；目录必须可写 |
| `JWT_SECRET` | 32+ 字节；修改后小程序用户需重新登录 |
| `WX_SECRET` | 必须配置；不要提交到 Git |
| `WX_MOCK` | 生产必须是 `0` |
| `ADMIN_JWT_SECRET` | 与 `JWT_SECRET` 不同；修改后管理员需重新登录 |
| `ADMIN_JWT_TTL_SECONDS` | 管理员 token 有效期，默认 28800（8 小时） |
| `ADMIN_ORIGINS` | 管理端与 API 跨域时设置；同源部署可省略 |
| `UPLOAD_DIR` | 上传文件目录，生产建议绝对路径 |
| `PUBLIC_BASE_URL` | 对外访问地址，用于生成图片完整 URL；生产填 HTTPS 域名 |

补充：

- `HOST`、`PORT`、`LOG_LEVEL` 不通过 Conda 设置；实际监听和日志级别以 uvicorn 启动参数为准。
- 如果管理端与 API 跨域，再设置：
  ```bash
  conda env config vars set ADMIN_ORIGINS='https://admin.example.com' -n labourrun
  conda deactivate
  conda activate labourrun
  ```
- 修改或删除变量：
  ```bash
  conda env config vars set KEY='new-value' -n labourrun
  conda env config vars unset KEY -n labourrun
  conda deactivate
  conda activate labourrun
  ```
- 含空格或特殊字符的密钥用单引号包裹。
- Conda 环境变量只对激活该环境后的进程生效；systemd 必须显式激活 Conda 环境。

安全提醒：

- `JWT_SECRET` 同时用于加密存储 `session_key`。修改 `JWT_SECRET` 后，用户需要重新 `wx.login()` 才能同步步数。
- Conda 环境变量包含密钥，限制 Conda 环境目录权限，不要把环境目录或密钥提交到 Git。
- `.env.example` 仅作为变量清单参考；本部署方式不使用 `.env` 文件。
- `data/` 目录不要放进静态资源目录。

### 3.3 初始化数据库和首个管理员

数据库表、活动/挑战种子数据会在应用启动时自动创建；管理员用 CLI 创建。

```bash
source /opt/miniconda3/etc/profile.d/conda.sh
conda activate labourrun
cd /opt/labourrun/LabourRunBack

python -m app.admin.bootstrap \
  --username admin \
  --password '请替换为强密码' \
  --display-name '超级管理员' \
  --role super_admin
```

密码要求：

- 至少 10 位
- 同时包含字母和数字

创建运营管理员：

```bash
# 保持 labourrun Conda 环境已激活
python -m app.admin.bootstrap \
  --username operator \
  --password '请替换为强密码' \
  --display-name '运营管理员' \
  --role operator
```

当前版本没有管理员密码重置页面；请妥善保存密码，并至少保留一个可用的超级管理员账号。

### 3.4 启动后端

#### 开发/临时启动

```bash
source /opt/miniconda3/etc/profile.d/conda.sh
conda activate labourrun
cd /opt/labourrun/LabourRunBack
uvicorn app.server:app \
  --host 127.0.0.1 \
  --port 3000 \
  --reload
```

#### systemd 生产启动

创建 `/etc/systemd/system/labourrun.service`：

```ini
[Unit]
Description=LabourRun FastAPI
After=network.target

[Service]
Type=simple
User=labourrun
Group=labourrun
WorkingDirectory=/opt/labourrun/LabourRunBack
Environment=HOME=/home/labourrun
ExecStart=/bin/bash -lc 'source /opt/miniconda3/etc/profile.d/conda.sh && conda activate labourrun && exec uvicorn app.server:app --host 127.0.0.1 --port 3000 --workers 1 --proxy-headers --log-level info'
Restart=always
RestartSec=3
UMask=0077

[Install]
WantedBy=multi-user.target
```

启动：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now labourrun
sudo systemctl status labourrun
```

查看日志：

```bash
sudo journalctl -u labourrun -f
```

说明：

- `ExecStart` 中的 `/opt/miniconda3` 替换为实际 `conda info --base` 路径。
- Conda 环境变量在 `conda activate labourrun` 时加载；不再使用 `EnvironmentFile` 或 `.env`。
- `labourrun` 用户需能读取 Conda 环境目录。
- SQLite 建议只跑 **1 个 worker**，避免多进程写锁竞争。
- 后端只监听 `127.0.0.1`，由 Nginx 对外提供 HTTPS。
- 如果不用 Nginx，必须自行配置 HTTPS 和防火墙，不建议直接暴露 3000 端口。

### 3.5 Nginx 与 HTTPS

#### 方案 A：FastAPI 托管管理端（推荐，单服务）

先构建管理端（见第 4 节），确保 `LabourRunAdmin/dist` 存在，再启动/重启后端。

Nginx：

```nginx
server {
    listen 80;
    server_name api.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name api.example.com;

    ssl_certificate     /etc/nginx/ssl/api.example.com.pem;
    ssl_certificate_key /etc/nginx/ssl/api.example.com.key;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 30s;
    }
}
```

访问：

- API：`https://api.example.com/api/v1`
- Swagger：`https://api.example.com/docs`
- 管理端：`https://api.example.com/admin/`
- 健康检查：`https://api.example.com/healthz`

#### 方案 B：Nginx 托管管理端静态文件

适合已有 Nginx 静态站点或希望前后端分开缓存的场景。

```nginx
server {
    listen 443 ssl http2;
    server_name api.example.com;

    ssl_certificate     /etc/nginx/ssl/api.example.com.pem;
    ssl_certificate_key /etc/nginx/ssl/api.example.com.key;

    location /api/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /uploads/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /admin/ {
        alias /opt/labourrun/LabourRunAdmin/dist/;
        index index.html;
        try_files $uri $uri/ /admin/index.html;
    }

    location = /admin {
        return 301 /admin/;
    }

    location /healthz {
        proxy_pass http://127.0.0.1:3000;
    }

    location /docs {
        proxy_pass http://127.0.0.1:3000;
    }
}
```

注意：

- 管理端 Vite `base` 和 Vue Router `base` 都是 `/admin/`；如果改路径，需要同时改 `vite.config.ts`、`src/router.ts` 和 Nginx/FastAPI 静态路由。
- `try_files` 用于 SPA 路由回退到 `index.html`。
- 如果 Nginx 托管管理端，FastAPI 的 `/admin` 不会被访问；两种方式不要同时混用同一个路径。
- 方案 B 下要确保 Nginx 运行用户对 `LabourRunAdmin/dist` 及父目录有读/执行权限，否则会出现 403/404；可按需执行 `chmod -R a+rX /opt/labourrun/LabourRunAdmin/dist`。

### 3.6 健康检查

```bash
curl -fsS http://127.0.0.1:3000/healthz
```

期望：

```json
{"status":"ok","version":"1.0.0"}
```

## 4. 管理端前端部署

### 4.1 开发环境

```bash
cd /opt/labourrun/LabourRunAdmin
npm install
npm run dev
```

访问：

```
http://<服务器局域网IP>:5173/admin/
```

例如服务器局域网 IP 为 `192.168.1.10`：

```
http://192.168.1.10:5173/admin/
```

说明：

- `vite.config.ts` 已设置 `server.host = '0.0.0.0'`，因此局域网其他机器可以访问开发服务器。
- 需要确保服务器防火墙放行 TCP 5173（仅开发环境）。例如仅允许局域网网段：
  ```bash
  sudo ufw allow from 192.168.0.0/16 to any port 5173 proto tcp
  ```
- Vite 已配置 `/api` 代理到 `http://127.0.0.1:3000`；后端仍可只监听本机 127.0.0.1，浏览器请求由 Vite 转发。
- 生产环境不要暴露 5173，使用第 4.2 节构建后的 `/admin/`（443）。

如果后端不在本机 3000 端口，修改 `vite.config.ts`：

```ts
server: {
  proxy: {
    '/api': {
      target: 'http://你的后端地址:3000',
      changeOrigin: true,
    },
  },
}
```

### 4.2 生产构建

```bash
cd /opt/labourrun/LabourRunAdmin
npm ci
npm run typecheck
npm run build
```

说明：

- `package-lock.json` 已锁定依赖；生产环境用 `npm ci` 可复现安装。
- `npm run build` 本身已包含 `vue-tsc --noEmit`；`npm run typecheck` 可单独执行。
- `dist/` 不提交到代码仓库，部署时构建。

输出：

```
LabourRunAdmin/dist/
```

如果使用 FastAPI 托管管理端：

1. 先构建 `dist`。
2. 再启动或重启 `labourrun` 服务，让 FastAPI 检测到 `dist` 并挂载 `/admin`。

```bash
sudo systemctl restart labourrun
```

如果使用 Nginx 托管，构建后无需重启后端，刷新 Nginx 即可。

### 4.3 访问与登录

- 地址：`https://api.example.com/admin/`
- 登录账号：第 3.3 节创建的管理员
- 管理员 token 存于浏览器 `sessionStorage`，默认 8 小时过期

### 4.4 使用说明

#### 概览

查看当前活动、当前挑战、报名总数、今日新增报名、最近审计日志。

#### 活动管理

可编辑：

- 活动名称
- 公告文案（首页顶部“延期：…”）
- 活动图片（上传/移除，后台自动裁剪、压缩）
- 活动规则（编号 + 内容，支持新增/删除/上移/下移）
- 活动开始/结束日期
- 活动状态：未开始 / 进行中 / 已结束

操作：

1. 打开“活动管理”。
2. 修改字段和规则；可上传活动图片。
3. 右侧查看小程序效果预览。
4. 点击“保存并发布”。
5. 小程序下次打开首页即可看到新内容。

活动图片：

- 支持 JPG/PNG/WebP，最大 10MB。
- 后台自动居中裁剪为 **750×400**，转 JPEG，quality 82，尽量 ≤200KB。
- 上传后先预览，点击“保存并发布”后小程序生效。
- 无图片或图片加载失败时，小程序回退到原来的蓝色“活动须知”装饰区。
- 旧图片文件暂不自动删除（审计日志可能引用），可后续定期清理。

注意：

- 规则至少 1 条、最多 20 条。
- 规则编号不能重复。
- 开始日期不能晚于结束日期。
- 保存即发布，没有草稿/回滚。

#### 挑战管理

可编辑：

- 挑战名称
- 开始/结束日期
- 目标步数
- 保证金（元，最多 2 位小数；后端存整数分）
- 参与人数（人工修正）
- 详细规则（标题 + 内容）
- 状态：未开始 / 进行中 / 已结束

操作：

1. 打开“挑战管理”。
2. 修改字段和规则。
3. 预览挑战卡和规则。
4. 点击“保存并发布”。
5. 小程序下次打开步数宝或“更多”页即可看到新内容。

#### 报名管理

- 按姓名/手机号/工作单位搜索。
- 按状态筛选：已报名 / 已取消。
- 分页查看。
- 点击行或“详情”查看完整报名信息。
- 手机号在列表默认脱敏，如 `138****8000`；详情中 super_admin 可见完整手机号，operator 只看到脱敏号码。
- 超级管理员可点击“导出 CSV”；运营管理员不可导出。
- 报名数据只读，管理端不提供编辑/删除。

CSV：

- UTF-8 BOM，Excel 可直接打开。
- 列：姓名、手机号、工作单位、状态、报名时间、更新时间、取消时间。

#### 审计日志

- 按管理员 ID、资源类型、日期范围筛选。
- 查看登录、退出、更新活动、更新挑战等操作。
- 点击详情查看修改前/修改后的 JSON 快照。
- 审计日志只读，不提供删除。

#### 管理员账号

当前版本不提供管理页面。使用 CLI 创建：

```bash

conda activate labourrun
cd /opt/labourrun/LabourRunBack
python -m app.admin.bootstrap \
  --username operator2 \
  --password '请替换为强密码' \
  --display-name '运营二号' \

```

## 5. 微信小程序部署与使用

### 5.1 微信公众平台配置

1. 确认小程序 AppID 与后端 `WX_APPID` 一致。
2. 配置 request 合法域名：`https://api.example.com`。
3. 配置隐私保护指引，说明收集姓名、电话、工作单位、微信运动步数。
4. 确认类目和微信运动相关能力可用。
5. 上传并发布小程序版本。

### 5.2 本地联调

1. 后端使用 `WX_MOCK=1` 启动。局域网联调时建议（路径按实际部署替换）：

### 5.4 用户流程

1. **启动**
   - 开发 mock 模式：使用固定 `mock:miniapp-demo`，不调用 `wx.login`。
   - 生产模式：小程序调用 `wx.login()` 获取 code。
   - 请求 `POST /api/v1/auth/login`。
   - 保存返回的 JWT，后续请求带 `Authorization: Bearer <token>`；401 时自动重新登录并重试一次。

2. **首页**
   - `GET /api/v1/home` 获取公告、规则、活动主图、当前报名。
   - 后台配置了 `imageUrl` 时展示活动主图；无图或加载失败时回退到原装饰区。
   - 填写姓名、电话、工作单位。
   - `POST /api/v1/registrations` 报名。
   - 修改 `PATCH /api/v1/registrations/{id}`。
   - 取消 `POST /api/v1/registrations/{id}/cancel`。
   - 取消后可再次报名，复用原记录。

3. **步数宝**
   - `GET /api/v1/steps` 获取兑换券余额、今日步数、挑战摘要。
   - 点击“同步最新步数”：
     - `wx.getWeRunData()` 获取 `encryptedData`、`iv`。
     - `POST /api/v1/steps/sync` 传给后端解密。
   - 点击“点击兑换”：
     - 生成 `requestId`。
     - `POST /api/v1/steps/exchange`。
   - 挑战“更多”：`GET /api/v1/challenges/current`。

4. **我**
   - `GET /api/v1/me` 获取用户资料。
   - `PATCH /api/v1/me` 修改昵称。
   - 头像、手机号绑定、排行榜、邀请/助力、每日提醒、商城资产本期未实现，前端使用静态占位。

### 5.5 业务规则

- 步数来源：微信运动 `wx.getWeRunData`。
- 每日可兑换步数上限：**12000 步**。
- 兑换比例：**10000 步 = 1.00 兑换券**。
- 金额向下取整到分。
- 示例：6638 步 → 0.66 兑换券；12000 步 → 1.20 兑换券。
- 未兑换步数每日零点自然失效；兑换券余额保留。
- 兑换 `requestId` 幂等，重复请求不会重复发放。

### 5.6 微信运动注意事项

- 用户必须授权“微信运动”，并在微信中开启微信运动。
- 未授权/未开启时步数可能为 0。
- 微信运动数据可能有延迟。
- 后端解密失败返回 1003，前端应重新 `wx.login()` 后重试。
- 修改 `JWT_SECRET` 会使旧 `session_key` 无法解密，用户需重新登录。

```bash
import sqlite3
from datetime import datetime

src_path = "/opt/labourrun/LabourRunBack/data/labourrun.sqlite"
dst_path = f"/opt/labourrun/backup/labourrun-{datetime.now():%Y%m%d-%H%M%S}.sqlite"

src = sqlite3.connect(src_path)
dst = sqlite3.connect(dst_path)
src.backup(dst)
dst.close()
src.close()
print(dst_path)
PY
```

同时备份活动图片：

```bash
tar -czf /opt/labourrun/backup/uploads-$(date +%F-%H%M%S).tar.gz \
  -C /opt/labourrun/LabourRunBack uploads
```

- SQLite 开启 WAL；`.backup` 可以在服务运行时安全备份。

## 8. 故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| `/admin/` 404 | `LabourRunAdmin/dist` 不存在 | 执行 `npm run build`，重启后端 |
| 管理端页面空白/资源 404 | Vite base 不是 `/admin/` | 检查 `vite.config.ts`、`router.ts` |
| 管理端登录 401 | 密码错误、账号禁用、`ADMIN_JWT_SECRET` 不一致 | 重新创建/确认密码，检查 Conda 环境变量是否在激活后生效 |
| Conda 环境变量不生效 | 设置后没有重新激活环境 | `conda deactivate` 后重新 `conda activate labourrun` |
| systemd 启动报 `conda: command not found` | 未 source `conda.sh` | 在 `ExecStart` 中用绝对路径 source，并确认路径正确 |
| 管理端 429 | 登录失败次数过多 | 等待 15 分钟；单进程限流，重启可清空 |
| 管理端请求 CORS 失败 | 跨域未配置 | 配置 `ADMIN_ORIGINS`，或同源/代理部署 |
| 局域网无法访问 5173 | 防火墙未放行或 Vite 未监听 0.0.0.0 | 放行 TCP 5173；确认 `vite.config.ts` 的 `server.host` 为 `0.0.0.0` |
| 管理端保存后小程序没变化 | 未保存成功/缓存 | 看审计日志；小程序重新进入页面 |
| 微信登录 1005 | 未配置 `WX_SECRET` | 填写 AppSecret，重启 |
| 微信登录 1004/502 | code 无效、AppSecret 错误、微信上游异常 | 重新 `wx.login()`；检查 AppSecret/网络 |
| 微信运动解密 1003 | session_key 失效、`JWT_SECRET` 变更、数据错误 | 前端重新登录；检查 JWT_SECRET |
| 步数一直为 0 | 未授权微信运动、未开启微信运动、数据延迟 | 引导用户开启；稍后再同步 |
| 兑换 3003 | 无可兑换步数 | 先同步步数；确认未全部兑换 |
| 兑换 3004 | 达到每日 12000 步上限 | 次日再兑换 |
| 兑换 3006 | 金额不足 0.01 兑换券 | 至少累计 100 步再兑换 |
| 报名 2001 | 用户/手机号已报名 | 修改已有报名或取消后重报 |
| SQLite `database is locked` | 多进程/多 worker 写冲突 | 只跑 1 个 worker；检查是否有重复服务 |
| 审计日志 IP 都是 127.0.0.1 | Nginx 未传 `X-Forwarded-For` | 增加代理头配置 |
| 时间显示不对 | 服务器时钟/时区 | 校准系统时间；业务日期固定 UTC+8 |
| 修改代码后管理端仍旧 | 浏览器缓存/未重新构建 | 重新构建、强刷、重启 |
| `npm install` 失败 | Node 版本/网络/registry | 使用 Node 20+，检查 npm 源 |
| `EBADENGINE @vueuse/core requires Node >=22` | `element-plus` 被升级到较新版本 | 保持 `element-plus` 2.9.3，或将 Node 升级到 22+ |
| `npm run build` 类型错误 | TypeScript/Vue 类型问题 | 先执行 `npm run typecheck`，按提示修复 |
| `npm ci` 失败 | 缺少/不匹配 `package-lock.json` | 先执行 `npm install` 生成锁文件，再提交并重试 |
| `vite build` 失败 | 依赖/TypeScript/路径 | 查看构建日志，修复后重试 |
