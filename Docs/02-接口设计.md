## 1. 架构

### 1.1 总体链路

```
微信小程序
   │  wx.request / wx.login / wx.getWeRunData
   ▼
FastAPI（/api/v1）
   │  JWT 鉴权、参数校验、业务规则
   ├── SQLite（users / registrations / daily_steps / coupons / challenges）
   └── 微信接口（code2Session）
```

### 1.2 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 语言 | Python 3.14（生产建议 3.12/3.13） | 当前环境已跑通 |
| Web 框架 | FastAPI 0.163.1 | 自动 OpenAPI 文档、Pydantic 校验 |
| 数据校验 | Pydantic 2.13.4 | 请求体/响应体类型 |
| 数据库 | SQLite（标准库 `sqlite3`） | 本地零依赖；仓储层可替换 MySQL/PostgreSQL |
| 鉴权 | PyJWT 2.13.0 | HS256，JWT 7 天 |
| 微信解密 | cryptography 49.0.0 | AES-128-CBC |
| 微信请求 | httpx 0.28.1 | `code2Session` |
| 测试 | pytest 9.2.0 + FastAPI TestClient | 16 项接口/解密测试 |

### 1.3 后端目录

```

    schema.sql       # 建表与索引
    seed.py          # 活动/挑战/配置种子

    deps.py          # JWT 当前用户依赖

    wx.py            # code2Session、微信运动解密
    response.py      # 统一响应包
    errors.py        # 错误码
    timeutil.py      # 上海时区、金额格式化
```

### 1.4 接口形态

采用 **读接口按页面聚合 + 写接口按资源拆分**：

- 读：`GET /home`、`GET /steps`、`GET /me` 一次返回一个 Tab 所需数据。
- 写：报名、步数同步、兑换、修改昵称按资源拆分，便于幂等、测试和后续扩展。
- 未来若增加管理后台/多端，可在现有 service 上补纯 REST 资源读接口。

## 2. 通用约定

### 2.1 Base URL 与 Content-Type

| 项目 | 约定 |
|---|---|
| Base URL | `/api/v1` |
| 本地 | `http://127.0.0.1:3000/api/v1` |
| 生产 | `https://<域名>/api/v1` |
| 请求 | `Content-Type: application/json; charset=utf-8` |
| 响应 | `Content-Type: application/json; charset=utf-8` |
| 文档 | `GET /docs`（Swagger UI）、`GET /redoc` |

### 2.2 鉴权

除登录、挑战详情、健康检查外，其余接口需要：

```
Authorization: Bearer <JWT>
```

- JWT 由 `POST /auth/login` 签发。
- JWT 有效期默认 604800 秒（7 天）。
- JWT payload：`sub`（用户 ID）、`iat`、`exp`。
- 401 时前端应重新 `wx.login()`，用新 code 调登录接口，再重试一次。

### 2.3 统一响应包

成功：

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "requestId": "8f0c2d7e-..."
}
```

失败：

```json
{
  "code": 2001,
  "message": "该手机号已报名",
  "data": null,
  "requestId": "8f0c2d7e-..."
}
```

- `requestId` 优先取请求头 `X-Request-Id`，否则服务端生成。
- 响应头同时返回 `X-Request-Id`。
- `data` 在失败时通常为 `null`；参数错误时为 `{ "errors": [...] }`。

### 2.4 HTTP 状态与业务错误码

| HTTP | 含义 | 典型业务码 |
|---|---|---|
| 200 | 成功 | 0 |
| 400 | 参数错误 | 4000 |
| 401 | 未登录 / token 过期 / 微信 session 失效 | 1001/1002/1003/1004 |
| 404 | 资源不存在 | 2002/4001/4040/5001 |
| 405 | 方法不允许 | 4050 |
| 409 | 重复/冲突 | 2001/2003 |
| 422 | 业务规则不满足 | 3002/3003/3004/3006 |
| 500 | 服务端错误 | 9001/9003/1005 |
| 502 | 微信上游异常 | 1004 |

业务错误码：

| code | HTTP | 含义 |
|---|---|---|
| 0 | 200 | 成功 |
| 1001 | 401 | 未登录或 token 无效 |
| 1002 | 401 | token 过期 |
| 1003 | 401 | 微信 session/微信运动数据失效，需要重新登录 |
| 1004 | 401/502 | 微信登录失败或微信上游不可用 |
| 1005 | 500 | 服务端未配置 WX_SECRET |
| 2001 | 409 | 用户或手机号已报名 |
| 2002 | 404 | 报名记录不存在或不属于当前用户 |
| 2003 | 409 | 报名已取消，不能修改 |
| 3002 | 422 | 暂无步数数据 |
| 3003 | 422 | 暂无可兑换步数 |
| 3004 | 422 | 已达到每日兑换上限 |
| 3006 | 422 | 可兑金额不足 0.01 兑换券 |
| 4000 | 400 | 参数校验失败 |
| 4001 | 404 | 挑战不存在 |
| 4040 | 404 | 路由不存在 |
| 4050 | 405 | 方法不允许 |
| 5001 | 404 | 活动不存在 |
| 9001 | 500 | 服务器内部错误 |
| 9002 | 400 | 生产模式收到 mockSteps |
| 9003 | 500 | 业务配置无效 |

### 2.5 数据类型

| 类型 | 约定 | 示例 |
|---|---|---|
| 用户/报名/兑换 ID | 字符串，带前缀 | `usr_...`、`reg_...`、`ex_...` |
| 兑换券金额 | 字符串，保留 2 位小数 | `"19.00"`、`"0.66"` |
| 兑换券存储 | SQLite 整数分 | `66` 表示 0.66 |
| 步数 | 整数 | `6638` |
| 日期 | `YYYY-MM-DD`（Asia/Shanghai） | `"2026-11-18"` |
| 时间戳 | ISO 8601 UTC | `"2026-11-17T08:00:00.000Z"` |
| 百分比/计数 | 整数 | `309` |
| 状态 | 字符串枚举 | `registered` / `cancelled` |

### 2.6 分页、幂等与时间

- 分页参数：`page`（默认 1）、`pageSize`（默认 20，最大 100）。
- 分页响应：`{ list, total, page, pageSize }`。
- 兑换幂等：请求体必须带 `requestId`，同一用户同一 `requestId` 只发放一次。
- 重复兑换请求返回原兑换记录 + 当前账户/步数汇总。
- 业务日期统一按 Asia/Shanghai；服务端用固定 UTC+8 计算，不依赖服务器时区。
- 每日清零不需要定时任务：`daily_steps` 按日期存储，查询“今天”自然切换。

## 3. 接口详情

### 3.1 登录

```
POST /api/v1/auth/login
```

鉴权：无。

请求体：

```json
{
  "code": "mock:demo"
}
```

- 真实环境：`code` 来自小程序 `wx.login()`。
- Mock 环境：`WX_MOCK=1`，可传 `mock:demo`、`mock:alice` 等。

响应 `data`：

```json
{
  "token": "eyJhbGciOiJIUzI1NiIs...",
  "expiresIn": 604800,
  "user": {
    "id": "usr_...",
    "nickname": null,
    "avatarUrl": null,
    "phone": null
  }
}
```

错误：

| code | 场景 |
|---|---|
| 1004 | 微信 code 无效 / 微信上游异常 |
| 1005 | 未配置 WX_SECRET |
| 4000 | code 为空或超长 |

说明：

- 首次登录自动创建用户和 0.00 兑换券账户。
- `openid` 只在服务端保存，不返回前端。
- 头像本期不实现，`avatarUrl` 为 `null`；手机号绑定本期不实现，`phone` 为 `null`。

### 3.3 新建/恢复报名

```
POST /api/v1/registrations
Authorization: Bearer <token>
```

请求体：

```json
{
  "realName": "张三",
  "phone": "13800138000",
  "company": "某某单位"
}
```

校验：

| 字段 | 规则 |
|---|---|
| `realName` | 必填，去除首尾空格，2–20 字符 |
| `phone` | 必填，中国大陆手机号，`^1[3-9]\d{9}$` |
| `company` | 必填，去除首尾空格，2–50 字符 |

响应 `data`：报名对象，字段同 3.2。

行为：

- 无报名记录：创建，状态 `registered`。
- 有已取消记录：复用原记录，更新姓名/电话/单位，状态恢复为 `registered`，清空 `cancelledAt`。
- 有已报名记录：返回 409，`code=2001`。
- 手机号被其他用户使用：返回 409，`code=2001`。
- 不发送短信验证码。

错误：

| code | 场景 |
|---|---|
| 2001 | 用户或手机号已报名 |
| 4000 | 参数校验失败 |
| 5001 | 活动不存在 |

响应 `data`：报名对象。

错误：

| code | 场景 |

| 2001 | 手机号已被其他报名使用 |
| 2002 | 报名记录不存在或不属于当前用户 |
| 2003 | 报名已取消，不能修改 |
| 4000 | 参数校验失败 |


### 3.7 同步微信运动步数

```
POST /api/v1/steps/sync
Authorization: Bearer <token>
```

真实模式请求体：

```json
{
  "encryptedData": "base64...",
  "iv": "base64..."
}
```

Mock 模式请求体：

```json
{
  "mockSteps": 6638
}
```

响应 `data`：

```json
{
  "couponAccount": {
    "balance": "0.00",
    "totalEarned": "0.00",
    "totalSpent": "0.00"
  },
  "stepSummary": {
    "todaySteps": 6638,
    "exchangedSteps": 0,
    "convertibleSteps": 6638,
    "convertibleCoupons": "0.66",
    "dailyCapSteps": 12000,
    "stepsPerCoupon": 10000,
    "lastSyncedAt": "2026-11-17T08:00:00.000Z"
  }
}
```

行为：

- 真实模式：后台用用户 `session_key` 做 AES-128-CBC 解密，校验 `watermark.appid`。
- 解密结果中的 `stepInfoList` 按日期 upsert；历史日期也保存。
- 今日没有数据时写入 0 步，保证页面可展示。
- 重复同步不会重置 `exchanged_steps`。
- Mock 模式仅当 `WX_MOCK=1`；生产模式收到 `mockSteps` 返回 9002。

错误：

| code | 场景 |
|---|---|
| 1003 | session_key 失效 / 解密失败 / watermark 不匹配 |
| 4000 | 请求体结构错误 |
| 9002 | 生产模式收到 mockSteps |

### 3.8 兑换

```
POST /api/v1/steps/exchange
Authorization: Bearer <token>
```

请求体：

```json
{
  "requestId": "req-20261117-0001"
}
```

- `requestId`：8–64 位，允许字母、数字、`_`、`-`；同一用户唯一。
- 一次性兑换全部可兑步数。

响应 `data`：

```json
{
  "exchange": {
    "id": "ex_...",
    "steps": 6638,
    "couponAmount": "0.66",
    "stepsPerCoupon": 10000,
    "createdAt": "2026-11-17T08:00:00.000Z"
  },
  "couponAccount": {
    "balance": "0.66",
    "totalEarned": "0.66",
    "totalSpent": "0.00"
  },
  "stepSummary": {
    "todaySteps": 6638,
    "exchangedSteps": 6638,
    "convertibleSteps": 0,
    "convertibleCoupons": "0.00",
    "dailyCapSteps": 12000,
    "stepsPerCoupon": 10000,
    "lastSyncedAt": "2026-11-17T08:00:00.000Z"
  }
}
```

计算：

```
可兑步数 = min(今日步数 − 今日已兑换步数, 12000 − 今日已兑换步数)
兑换券分 = floor(可兑步数 × 100 / 10000)
```

示例：

| 可兑步数 | 兑换券 |
|---|---|
| 6,638 | 0.66 |
| 12,000 | 1.20 |
| 99 | 不足 0.01，拒绝 |

幂等：

- 同一 `requestId` 重复请求返回原 `exchange`，不会重复加券。
- 返回的 `couponAccount` / `stepSummary` 是当前最新状态。

错误：

| code | 场景 |
|---|---|
| 3002 | 今日没有步数数据 |
| 3003 | 暂无可兑换步数 |
| 3004 | 已达到每日兑换上限 |
| 3006 | 可兑金额不足 0.01 兑换券 |
| 4000 | requestId 格式错误 |

## 4. 业务规则

### 4.1 报名

- 同一活动、同一用户只能有一条报名记录。
- 同一活动、同一手机号只能有一条报名记录。
- 修改报名时重新校验手机号唯一性。
- 取消报名为软删除：保留记录，`status=cancelled`。
- 取消后再次报名复用原记录，恢复为 `registered`，不产生新记录。
- 报名电话手动输入，不做短信验证。

### 4.2 步数同步

- 数据来源：微信运动 `wx.getWeRunData`。
- 前端传 `encryptedData`、`iv`；后台用 `session_key` 解密。
- 解密后校验 `watermark.appid` 与 `WX_APPID` 一致。
- `stepInfoList` 按日期 upsert；历史日期保存，今日无数据写 0。
- 同步不重置当日 `exchanged_steps`。
- 微信 session 失效返回 1003，前端重新 `wx.login()` 后重试。

### 4.3 兑换

- 每日可兑换步数上限：**12000 步**。
- 兑换比例：**10000 步 = 1.00 兑换券**。
- 金额向下取整到分：`floor(steps × 100 / 10000)`。
- 一次性兑换全部可兑步数，不支持部分兑换。
- 可兑步数为 0、达到上限、金额不足 0.01 分别返回 3003/3004/3006。
- 兑换在单个 SQLite 事务内更新步数、账户、流水、兑换记录。
- `requestId` 幂等，重复请求不重复发放。
- 未兑换步数每日零点自然失效；兑换券余额长期保留。

### 4.4 挑战

- 挑战配置、目标步数、保证金、参与人数、详细规则由后台下发。
- 本期只读；参赛、保证金、完成/失败判定均为占位。
- `participantCount` 当前为种子值 309，不随报名变化。

### 4.5 占位与头像

- 排行榜、邀请/助力、每日提醒、商城、订单、积分、优惠券、卡券、收藏、足迹：**不提供接口**。
- 前端这些区域使用静态 0 或静态文案。
- 头像上传：**不实现**；`avatarUrl` 本期为 `null`，`PATCH /me` 只改昵称。
- 不创建占位业务表。

## 5. 数据模型

| 表 | 关键字段 | 说明 |
|---|---|---|
| `users` | `id`、`openid`、`unionid`、`avatar_url`、`nickname`、`phone`、`session_key_enc`、`created_at`、`updated_at` | `openid` 唯一；`session_key` 用 Fernet 加密存储 |
| `activities` | `id`、`name`、`notice_text`、`rules_json`、`start_date`、`end_date`、`status` | 首页公告/规则 |
| `registrations` | `id`、`activity_id`、`user_id`、`real_name`、`phone`、`company`、`status`、`created_at`、`updated_at`、`cancelled_at` | 唯一索引：活动+用户、活动+手机号 |
| `daily_steps` | `id`、`user_id`、`stat_date`、`steps`、`exchanged_steps`、`source`、`synced_at`、`created_at`、`updated_at` | 唯一索引：用户+日期 |
| `exchange_records` | `id`、`user_id`、`stat_date`、`steps`、`coupon_cents`、`steps_per_coupon`、`request_id`、`status`、`created_at` | 唯一索引：用户+requestId |
| `coupon_accounts` | `user_id`、`balance_cents`、`total_earned_cents`、`total_spent_cents`、`updated_at` | 金额存整数分 |
| `coupon_ledger` | `id`、`user_id`、`type`、`amount_cents`、`balance_after_cents`、`ref_type`、`ref_id`、`created_at` | 兑换流水 |
| `challenges` | `id`、`title`、`start_date`、`end_date`、`target_steps`、`deposit_cents`、`participant_count`、`rules_json`、`status` | 只读配置 |
| `app_config` | `key`、`value` | `daily_cap_steps=12000`、`steps_per_coupon=10000` |

种子数据：

- 活动：`act_default`，公告“延期：10月27日-12月27日”，规则 4 条，状态 `ongoing`。
- 挑战：`ch_default`，开始日期 `2026-11-18`，目标 12000 步，保证金 0.00，参与人数 309，状态 `upcoming`。
- 配置：`daily_cap_steps=12000`，`steps_per_coupon=10000`。

## 6. 前端调用映射

| 页面/时机 | 调用 |
|---|---|
| 小程序启动 | `POST /auth/login`，保存 token |
| 首页进入 | `GET /home` |
| 首页提交报名 | `POST /registrations` |
| 首页保存修改 | `PATCH /registrations/{id}` |
| 首页取消报名 | `POST /registrations/{id}/cancel` |
| 步数宝进入 | `GET /steps` |
| 点击“同步最新步数” | `wx.getWeRunData()` → `POST /steps/sync` |
| 点击“点击兑换” | 生成 `requestId` → `POST /steps/exchange` |
| 挑战“更多” | `GET /challenges/current` |
| 兑换券明细（后续） | `GET /coupons/ledger` |
| 我页进入 | `GET /me` |
| 保存昵称 | `PATCH /me` |
| 排行榜/邀请/提醒/商城 | 前端静态占位，不请求接口 |

鉴权失败处理：

1. 收到 401 / `code=1001/1002/1003`。
2. 调用 `wx.login()` 获取新 code。
3. 调 `POST /auth/login` 换新 token。
4. 重试原请求一次；仍失败则提示用户。
